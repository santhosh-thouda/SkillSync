# SkillSync: Enterprise Security Architecture Documentation

## 1. Introduction
Security is the cornerstone of the SkillSync platform. Given its nature as a mentorship and skill-sharing network, protecting user identities, personal data, and professional intellectual property is paramount. SkillSync implements a multi-layered, **Zero-Trust Security Model** that combines perimeter defense, stateless authentication, role-based authorization, and secure service-to-service communication.

---

## 2. Security Pillars
SkillSync's security architecture is built on five core pillars:
1.  **Identity & Access Management (IAM)**: Centralized authentication via the Auth Service.
2.  **Stateless Authorization**: Leveraging JSON Web Tokens (JWT) for secure, scalable session management.
3.  **Role-Based Access Control (RBAC)**: Fine-grained permissions enforced at the method and endpoint levels.
4.  **Data Protection**: Encryption of sensitive data at rest and in transit.
5.  **Perimeter Defense**: API Gateway acting as a unified security filter and orchestrator.

---

## 3. Perimeter Security: The API Gateway
The **API Gateway** (:8080) is the first line of defense.
- **Unified Entry Point**: All external traffic must pass through the Gateway; internal microservices are not exposed to the public internet.
- **CORS Management**: Centralized configuration to prevent unauthorized cross-origin requests while allowing trusted frontend domains.
- **Request Sanitization**: Filters out malicious headers and ensures requests conform to expected formats before forwarding them to internal services.

---

## 4. Identity & Authentication (Auth Service)
The **Auth Service** (:8081) acts as the platform's Identity Provider (IdP).

### 4.1 Registration & Hashing
- When a user registers, their password is never stored in plain text.
- **BCrypt Algorithm**: SkillSync uses `BCryptPasswordEncoder` with a configurable "strength" (salt rounds). BCrypt is a slow-hashing algorithm specifically designed to resist brute-force and rainbow table attacks.
- **Registration Flow**: 
    - Input Validation (Email format, Password strength).
    - Password Hashing.
    - Persistence in the `auth_db`.

### 4.2 Authentication (Login)
1.  **Verification**: The user provides email and password.
2.  **Validation**: The Auth Service compares the raw password with the hashed version in the database.
3.  **Token Generation**: Upon successful verification, the service generates a signed JWT.

---

## 5. Stateless Authorization: JWT Implementation

### 5.1 Token Anatomy
SkillSync JWTs follow the RFC 7519 standard and contain three parts:
1.  **Header**: Specifies the algorithm (HS256) and token type.
2.  **Payload (Claims)**:
    - `sub`: The user's email (Subject).
    - `userId`: Internal database identifier.
    - `role`: The user's platform role (LEARNER, MENTOR, ADMIN).
    - `iat`: Issued at timestamp.
    - `exp`: Expiration timestamp (e.g., 24 hours).
3.  **Signature**: Generated by hashing the Header and Payload with a secret key (`JWT_SECRET`).

### 5.2 Token Validation Logic
Every microservice (User, Mentor, Session, etc.) is responsible for validating the JWT.
- **Filter**: `JwtAuthenticationFilter` intercepts every incoming request.
- **Logic**:
    - Extract the `Bearer` token from the `Authorization` header.
    - Verify the signature using the shared `JWT_SECRET`.
    - Check for token expiration.
    - Populate the `SecurityContextHolder` with an `Authentication` object.

## 6. Role-Based Access Control (RBAC)

SkillSync implements strict RBAC to ensure users can only perform actions appropriate for their role.

### 6.1 Defined Roles
- **ROLE_LEARNER**: Can search mentors, request sessions, join study groups, and leave reviews.
- **ROLE_MENTOR**: Can manage their profile, accept/reject sessions, and manage availability.
- **ROLE_ADMIN**: Can approve mentors, manage all users, and oversee platform health.

### 6.2 Permission Enforcement
Permissions are enforced using Spring Security's `@PreAuthorize` and `@Secured` annotations.

| Resource | Required Role |
| :--- | :--- |
| `POST /sessions/request` | `ROLE_LEARNER` |
| `PUT /sessions/{id}/accept` | `ROLE_MENTOR` |
| `PUT /mentors/{id}/approve` | `ROLE_ADMIN` |
| `GET /users/all` | `ROLE_ADMIN` |

---

## 7. Service-to-Service Security

In a microservices mesh, service-to-service communication must also be secure.

### 7.1 Private Networking
All containers reside on an internal Docker bridge network. They communicate using service names (e.g., `http://auth-service:8081`). This network is isolated from the host machine.

### 7.2 Header Propagation (Feign)
When one service calls another (e.g., Auth Service calling User Service), it propagates the `Authorization` header. This ensures the downstream service can still identify the original user and enforce role-based rules.

---

## 8. Data Security & Integrity

### 8.1 Database Security
- **PostgreSQL Isolation**: Each microservice uses a dedicated database schema with its own credentials.
- **Secret Management**: Database passwords and JWT keys are stored in the `Config Server` and injected into containers at runtime. They are never committed to the core application source code.

### 8.2 Transport Security (Production)
- In a production environment, all communication (Client to Gateway and Service to Service) should be encrypted via **TLS/SSL**.
- The API Gateway acts as the SSL Termination point.

---

## 9. Security Monitoring & Auditing

### 9.1 Distributed Tracing
Trace IDs are used to track every request. If an unauthorized access attempt occurs, the security logs will show exactly which service blocked the request and provide the associated `traceId` for forensic analysis.

### 9.2 Health & Actuator
Actuator endpoints (like `/actuator/health`) are used to monitor the security status of each service. Access to these endpoints is restricted to internal infrastructure components.

---

## 10. Conclusion
The SkillSync security architecture is designed to be comprehensive yet lightweight. By combining the strengths of Spring Security, JWT, and microservices isolation, we have created a platform that is resistant to common attack vectors (CSRF, Brute Force, Unauthorized Access) while remaining highly scalable and developer-friendly.
