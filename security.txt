## 2. Perimeter Security & API Gateway Protection

The **API Gateway** acts as the first line of defense for the SkillSync ecosystem.

### 2.1 Centralized Authentication
All incoming requests to the platform are intercepted by the Gateway.
- **JWT Integrity Check**: The gateway validates the signature of the incoming JWT. If the token is missing, malformed, or has an invalid signature, the request is rejected with a `401 Unauthorized`.
- **Statelessness**: No session data is stored on the server. The entire identity of the user is encapsulated in the JWT claims.

### 2.2 CORS Policy (Cross-Origin Resource Sharing)
To prevent unauthorized domains from making requests to our backend:
- **Whitelisting**: Only the official frontend domain is permitted to interact with the API.
- **Method Restriction**: Specific HTTP methods (GET, POST, PUT, DELETE) are permitted only for authenticated sessions.

### 2.3 Rate Limiting & DoS Protection
The gateway implements bucket-based rate limiting to prevent brute-force attacks and resource exhaustion.
- **IP-Based Throttling**: Limits the number of requests per second from a single IP address.
- **User-Based Throttling**: Limits requests based on the authenticated user ID.

## 3. Identity & Access Management (IAM)

The **Auth Service** is the central authority for identity lifecycle management.

### 3.1 Credential Hardening
- **Password Hashing**: Passwords are never stored in plain text. We utilize the **BCrypt** hashing algorithm with a cost factor of 12.
- **Salt Management**: BCrypt automatically manages salts, making the system resilient to rainbow table attacks.

### 3.2 Role-Based Access Control (RBAC)
SkillSync enforces a strict role hierarchy:
- **LEARNER**: Can browse mentors, book sessions, and join groups.
- **MENTOR**: Can manage their profile, accept sessions, and communicate in groups.
- **ADMIN**: Has global access to platform metrics, user management, and approval workflows.

### 3.3 Token Lifecycle
- **Short-Lived JWTs**: Tokens have a 1-hour expiration to minimize the window of opportunity for intercepted tokens.
- **Refresh Tokens**: Long-lived refresh tokens allow users to stay logged in securely without exposing their password frequently.

---

## 4. In-Transit & At-Rest Data Protection

### 4.1 Transport Layer Security (TLS)
- **HTTPS Enforcement**: All external and internal communication is encrypted using **TLS 1.3**.
- **Internal mTLS**: (Planned) Mutual TLS between microservices ensures that even internal traffic is cryptographically isolated.

### 4.2 Database Security
- **Encryption at Rest**: PostgreSQL tablespaces are encrypted using native cloud-provider keys.
- **Parameterization**: All database queries utilize **JPA Criteria API** or **Named Parameters** to prevent SQL Injection (SQLi) attacks.

---

## 5. Defensive Programming & Logic Security

### 5.1 Input Validation (JSR-303)
Every API endpoint validates its input before processing business logic.
- **Sanitization**: Prevents Cross-Site Scripting (XSS) by stripping dangerous HTML tags.
- **Type Checking**: Ensures that data matches expected formats (e.g., email regex, range limits).

### 5.2 Exception Sanitization
Custom exception handlers ensure that sensitive system information (e.g., stack traces, DB schema names) is never exposed to the client. Only meaningful, localized error messages are returned.

---

## 6. Real-time Communication Security (WebSockets)

### 6.1 STOMP Interceptors
WebSocket connections are secured using a `ChannelInterceptor` that performs a JWT handshake before allowing a user to subscribe to a topic.
- **Group Isolation**: Users can only subscribe to `/topic/group.{id}` if they are verified members of that group.

---

## 7. Security Observability & Auditing

### 7.1 Distributed Tracing (Zipkin)
Every security event (login, unauthorized access attempt) is tagged with a `traceId`, allowing the security team to reconstruct the entire request path during an audit.

### 7.2 Audit Logging (AOP)
Critical business operations (e.g., changing a mentor's rating, approving an application) are intercepted by a Spring AOP Aspect that logs the actor, timestamp, and action to a secure audit log.
